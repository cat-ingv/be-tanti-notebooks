The metadata schema consists of 4 main entities:

  - **experiments**: represents the fundamental element of the schema containing all general information about the experiment. The table has the following attributes:
      - *id(primary key, text)*: unique identifier of the experiment
      - *name(text)*: name of the experiment
      - *description(text)*: description of the experiment
      - *keywords (text[])*: list of keywords describing the experiment
      - *license (text)*: license of the experiment
      - *open_access(boolean)*:
      - *embargo_date (datetime)*:

  - **simulations**: represents a single run of a simulation containing all details about the simulation execution. The table has the following attributes:
      - *id(primary key, text)*: unique identifier of the simulation run
      - *name(text)*: name of the simulation run
      - *description(text)*: description of the simulation run
      - *path(text)*: relative path of the simulation run sub-folder in the main experiment directory
      - *fk_exp_id(foreign key, text)*: identifier of the experiment to which the simulation belongs
    This table contains 53550 simulations runs: 25021 belongs to BS-type scenarios and 28509 belongs to PS-type scenarios.

  - **datasets**: represents a single file used or generated by a simulation run. Each dataset contains general information related to the file. The table has the following attributes:
      - *id(primary key, text)*: unique identifier of the dataset
      - *name(text)*: name of the dataset
      - *description(text)*: description of the dataset
      - *type(text)*: type of dataset. There are 5 types of datasets:
          - *global_input*: the dataset is used as Input by all Simulation Runs of the experiment.
          - *global_product:* derived Output, i.e. resulting from a post-processing of all Simulation Runs.
          - *input*: the dataset is used as Input by a single Simulation Run.
          - *output*: the dataset is the Output of one or more Simulation Runs.
          - *product*: the dataset is a derived Output, i.e. resulting from a post-processing, of one or more Simulation Runs.
      - *fileFormat(text)*: format of the file
      - *path(text)*: relative path of the file  in the main experiment directory
      - *shared (boolean)*: specifies if the dataset is a Global Input, i.e. shared with all simulation runs of the experiment, or not.
      - *spatialCoverage (float[])*: bounding box (min_lon, min_lat, max_lon, max_lat) of the geographical region covered by the dataset [define a common coordinate system?]
      - *fk_exp_id(foreign key, text)*: identifier of the experiment where the Global Input dataset is shared
    This table contains 214208 datasets. In particular, we have 8 Global Input and 4 datasets (1 Input and 3 Data Product) for each of 53550 simulation runs.

  - **parameters_v1**: represents additional parameters used to enrich a single simulation run. Each simulation run can have associated a different set of parameters describing the simulated scenario, the configuration of the simulation and the outputs produced by the simulation. The table has the following attributes:
      - *id (primary key,text)*: unique id of the parameter
      - *seismicity_type*: string identifying the seismicity type of the scenario of the simulation, i.e. ‘PS’ or ‘BS’
      - *magnitude*: magnitude value of the earthquake source
      - *manning_coeff*: value of water-bottom friction (Manning coefficient)
      - *fault_centre_lat*: latitude of the centre of the BS-type source fault
      - *fault_centre_lon*: longitude of the centre of the BS-type source fault
      - *fault_centre_depth*: depth of the centre of the BS-type source fault
      - *dip*: value of the dip of the BS-type source fault float BS
      - *rake*: value of the rake of the BS-type source fault float BS
      - *strike*: value of the strike of the BS-type source fault float BS
      - *slip* value of the slip of the BS-type source fault float BS
      - *mesh_faults*: 3D multipolygon describing the triangular mesh of the PS-type source faults 
      - *mesh_fault_bbox*: 3D bounding box containing the mesh fault
      - *mesh_fault_bc_lat*: latitude of the baricenter of the PS mesh fault
      - *mesh_fault_bc_lon*: longitude of the baricenter of the PS mesh fault
      - *mesh_fault_rake_uniform*: uniform rake angle across the mesh fault float PS
      - *mesh_fault_slip_distr*: distribution of slip values over triangles of the mesh fault
      - *mesh_fault_slip_max*: maximum value of slip distribution over the mesh fault
      - *mesh_fault_slip_min*: minimum value of slip distribution over the mesh fault
      - *mesh_fault_slip_avg*: average value of slip distribution over the mesh fault
      - *max_ts_ct*: max of the time series at the site of Catania (37.55◦N, 15.52◦E)
      - *max_ts_sr*: max of the time series at the site of Siracusa (36.99◦N, 15.33◦E)
      - *arrival_time_ct*: arrival time (seconds) at the site of Catania (37.55◦N, 15.52◦E)
      - *arrival_time_sr*: arrival time (seconds) at the site of Siracusa (36.99◦N, 15.33◦E)
      - *list_rates*: list of occurrence rates of the scenario
      - *avg_rate*: average occurrence rate of the scenario
      - *fk_sr_id (foreign key, text)*: identifier of the simulation run to which the parameter is associated

The above entities are interconnected each others by the following relationships:
  - **experiments-simulations**: one-to-many relation between an experiment and its simulations. This relation is pivotal to keep track of all simulation runs performed during an experiment.
  - **experiment-datasets**: one-to-many relation between an experiment and its datasets. The latter are the datasets used as input (Global Input) by all simulation runs of the experiment.
  - **simulations-datasets**: many-to-many relation between simulation runs and datasets. A simulation run has multiple datasets associated (e.g. input and output datasets, data products) and, at the same time, the same dataset can be associated with multiple simulation runs (e.g. datasets obtained by combining results from multiple simulation runs). This relation is implemented by using the join-table rel_sr_ds.
  - **simulations-parameters**: one-to-many relation between a simulation run and its additional parameters. Each simulation run can be associated with additional parameters that help to characterize the different simulation scenarios.
